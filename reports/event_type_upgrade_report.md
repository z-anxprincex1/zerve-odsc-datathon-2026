## Recommended Modeling Use

1. Use `subscription_upgraded` only to define the label and first-upgrade timestamp.
2. Build a strict observation window before upgrade, such as first 24 hours, first 3 days, first 7 days, or first N events.
3. Exclude all events at or after each user's first upgrade timestamp.
4. Start with safer behavioral families: creation/workspace behavior, AI/agent behavior, deployment behavior, and early lifecycle/onboarding.
5. Treat commercial and credit events as separate experiments because they may be extremely predictive but leakage-prone.
